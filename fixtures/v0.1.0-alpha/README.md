# AZBFT v0.1.0-alpha Conformance Fixtures

These artifacts provide a fixed, reproducible public boundary for canonical
encoding, signatures, quorum validation, timeout validation, equivocation,
reconfiguration and finality transcript verification.

All identities are deterministic, low-entropy test identities derived from the
public seeds in `MANIFEST.txt`. They must never be used for production keys,
validator identities, operator authorization or any account holding value.
No secret or production key material is included.

## Finality transcripts

- `finality-valid.azbft`: four-validator, five-block deterministic finality
  transcript generated with devnet seed 42.
- `finality-invalid-qc.azbft`: the same transcript with one byte of the final
  commit-QC signature changed.

Expected verifier behavior from the repository root:

```bash
cargo run -p azbft-cli --bin azbft -- \
  verify fixtures/v0.1.0-alpha/finality-valid.azbft
# exit 0; prints: verified 5 finalized blocks

cargo run -p azbft-cli --bin azbft -- \
  verify fixtures/v0.1.0-alpha/finality-invalid-qc.azbft
# non-zero exit; the corrupted certificate is rejected
```

## Certificate and message vectors

All `.borsh` files use the canonical encoding defined by the versioned protocol
specification.

- `validator-set.borsh`: four equal-stake secp256k1 test validators; quorum 3.
- `vote.borsh`, `vote-digest.bin`, `vote-signature.bin`: one canonical vote, its
  round-binding digest and the domain-separated signature by validator 1.
- `qc-valid.borsh`: three-of-four vote quorum for round 7.
- `qc-invalid-below-quorum.borsh`: two-of-four signatures and expected rejection.
- `tc-valid-epoch-0.borsh`: three-of-four timeout quorum for epoch 0, round 9.
- `tc-invalid-below-quorum-epoch-0.borsh`: two-of-four timeout signatures and
  expected rejection.
- `equivocation-proof.borsh`: two valid conflicting round-11 votes by validator 1.
- `reconfiguration-evidence-removal.borsh`: removal of validator 1 justified by
  that equivocation proof, without operator authorization.

`MANIFEST.txt` records test identities and expected validity. `BLAKE3SUMS`
commits to every generated artifact other than itself and this explanatory file.
The Rust conformance test decodes and verifies the semantic expectations in the
builder before comparing every generated byte with the committed files.

## Reproduction

Generate into a new directory; the tool refuses to overwrite an existing path:

```bash
output_dir=$(mktemp -d)/azbft-v0.1.0-alpha
cargo run -p azbft-devnet --example generate_conformance -- "$output_dir"
diff -r fixtures/v0.1.0-alpha "$output_dir" \
  --exclude README.md
```

A byte difference indicates an encoding, cryptographic or deterministic-devnet
change and requires an explicit compatibility decision before release.
